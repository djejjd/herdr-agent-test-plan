# 执行面：并发、工作区、额度与工具预算

## 1. 并发与工作区

| 类型 | 建议上限 | 说明 |
|---|---|---|
| 监督者 | 恒 1 | 多头指挥必然打架 |
| 写代码执行者 | ≤2（默认，最多 3） | 多一个多一份冲突面与消耗 |
| 只读调研 | ≤2 | 控制证据量 |
| 总活跃 | ≤4 | 超出只是互相打断 |

- **并行写任务强制独立 worktree + 分支 + owners 登记**；单人任务不强制。
- `owners.md`：文件/模块 → owner → 任务ID → worktree → 起止；派工前查，冲突排队。
- **部署互斥**：同一时刻只允许一个 agent 写工作区外配置或执行部署，先登记。
- 提交只含任务范围文件；commit 正文带任务ID。
- 后合者解决冲突并报告；禁止对主分支强推或改写已发布历史。

## 2. 额度与工具预算

原则：监督者只裁决，不调查；翻日志、跑长测试、通读实现一律下沉。

| 动作 | 建议 | 避免 |
|---|---|---|
| 读文件 | 每轮最小片段 | 通读实现、逐个看日志 |
| 看 diff | `--stat` + 关键片段 | 全量逐行 |
| 跑测试 | 抽查一次 | 每轮全量 |
| 证据 | 路径 + 一句结论 | 大段输出进对话 |

- 每轮建议 ≤6 次工具调用；超预算先裁决、请示或转交。
- 例外须标注「预算例外：原因」：合并前核对、用户要求深挖、阻断排查。
- 禁止：整屏 read 抓进度、重复读同一文件、逐条翻日志（改要 grep 结论）。

## 3. 交付触发（禁止轮询）

1. 执行者完成/阻塞/需裁决时主动发交付卡；监督者只在事件到达时工作。
2. 不得用定时 wait/read 探测进度；需要状态时发「状态请求」，执行者回一行。
3. 长任务每约 5 分钟无事件，执行者发心跳：任务ID｜当前步骤｜下一步｜是否阻塞。

## 4. 阈值与通报

- 上下文 >50% 或额度 <30%：只裁决模式。
- 上下文 >70% 或额度 <15%：主动提出交接。
- 同一任务连续 3 轮无进展：停下问用户。
- 触发任一阈值，回复首行固定：
  `ALERT｜CTX=xx%｜QUOTA=xx%｜建议=降档|拆任务|交接|暂停`，并写明要用户决定什么。

## 5. 模型档位建议

| 档位 | 适用 |
|---|---|
| 低 | 格式化、搬运数据、单文件小改、跑命令、核对 |
| 中 | 常规实现、补测试、一般 bug、文档、验收复核 |
| 高 | 架构设计、疑难定位、跨模块重构、复杂裁决 |

- 监督者默认中档，复杂裁决升档后降回；任务边界换档，避免中途切换。
- 高档更耗额度：紧张时降档并缩短任务。

## 6. 反例（本次会话）

- 监督者整屏 read 看进度、同一日志翻三遍、用 wait 轮询。
- 监督者替执行者查根因（翻实现、手跑接口）。
- 执行者只回「完成了」没有卡；证据给结论不给命令。
- 共享工作区并行改同一文件，导致函数被静默删除。

## 7. 审批矩阵

| 类别 | 处理 |
|---|---|
| 必须用户逐项批准 | 合并/强推/改已发布历史；删分支或数据；发布与打标签；永久部署到工作区外；装全局依赖；新凭据或扩大范围；高风险不可逆；产品取舍 |
| 不用逐次批准 | 只读调查；本地测试与检查；契约内代码与测试；纯视觉/文案微调（无逻辑数据权限变化、可回滚）；临时截图与 fixture（不激活窗口、事后清理并标注）；本地未推送提交 |
| 灰区（监督者裁） | 跨模块但契约内；视觉超出既有设计语言（先给样图，走待批通报但不阻塞其它工作） |

判定顺序：先看是否不可逆或越界 → 是则要用户批；否则看是否在可写范围内 → 是则自理；两可则监督者裁并登记。

**用户负担上限**：每个任务最多 1 次用户真机验证，并把这 1 次与其它需要用户动手的动作合并成一次；已知点不开的通知（见 §8）禁止让用户去点。所有指向用户的动作都要入账（行ID + 消息ID），按任务统计每任务 ≤1 条。

## 8. 怎么让用户看到（通知到达，方案未实现）

1. **主通道**：macOS 系统通知，标题「需要你批准」，正文一句话含三要素（要你做什么 / 不做会怎样 / 去哪看）。
   - 通知样式设为「提醒」，不自动消失；未处理每 20 分钟重复一次，最多 3 次。
2. **兜底**：`cat ~/ai/collab/pending.md` 随时查；该文件为唯一账本，一行一条。
3. **可选**：Herdr 侧栏角标（监督者等待时上报等待状态），需先验证且不干扰现有集成。
4. **已知限制**：本机系统通知点击打不开（macOS 27 + terminal-notifier 失效），通知只负责让你看到，回到 Herdr 按标签找。
5. **实现状态（截至 2026-11-14）**：本节是方案；「每 20 分钟重复、最多 3 次」尚未实现，落地前不会自动提醒。实现任务须单独立项并验证。

## 9. 运行前置与临时资源收尾

- 开工先核对真实产品、工作区、加载路径与基线；不能从启动目录推断正在改的产品。优先复用用户已用的运行器，模型选择与运行器选择分开，不凭帮助示例替换真实入口。
- 任务短名须核验实际界面显示；只写标签不算命名完成。任务名与产品身份分别核对，不能用任务名替换产品身份。
- 共享 Git 元数据等前置操作若超出执行者沙箱，由监督者在既有授权内完成窄范围操作；不因此扩大执行者权限。
- 隔离测试优先复用一个实例；登记 `ownerTask`、PID、程序实际持有的 `identityPath`（如 socket 或文件）和退出证据。关闭窗口或删除临时 home 不等于进程退出。
- 交付前只读核验：声称 `exited` 但 PID 仍活必须拒绝；归属、PID 或身份不可确认时标为 `needs-verify`，不得自动终止未知进程。清理仅限确认属于本任务的测试资源，先确认退出再删除临时目录。
- 检查器只读，不启动 GUI 或 Agent、不安装全局依赖、不终止进程；项目检查命令由派工卡指定，具体命令写项目文档。
