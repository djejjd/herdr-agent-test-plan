# 多 Agent 协作（总纲与索引）

跨项目通用操作规范。纪律在 `~/ai/rules.md` §6；本文件只写总纲与入口，
细节拆到按类型的两份文件，避免单文件膨胀：

| 文件 | 内容 |
|---|---|
| `~/ai/collab/work.md` | 派工契约、交付卡与证据分级、验收门、合并门 |
| `~/ai/collab/ops.md` | 并发/worktree/owners、额度与工具预算、模型档位、阈值通报、反例 |
| `~/ai/collab/pending.md` | 待批账本（唯一，监督方单写；终端「待批 N」读取） |

## 1. 层级与职责

| 角色 | 只做什么 | 明确不做 |
|---|---|---|
| 用户 | 不可逆操作、权限、产品取舍 | 技术裁决 |
| 监督者（恒 1） | 拆解、派工、收件即裁、汇总、对用户单口 | 亲自实现、重复下属调查 |
| 执行者（N） | 契约内实现与自测、按模板交卡 | 越范围、自行扩任务、派工 |

换监督者必须显式交接：已改内容、未提交状态、验证结果、剩余风险、文件所有权。

## 2. 状态机与停滞

- 任务：待派 → 执行中 → 待审 → 返修 / 待用户 → 已验收 / 暂缓。
- `working` 只表示进程在跑，不表示有进展。
- 停滞：有可做项却空闲，或结束语只说「等你验收」而无具体裁决项。
- 结束回合前必须给「剩余裁决」或「无」；约 5 分钟无交付报证据或阻断。
- 监督者收件即裁，不把「已读」当「已处理」；禁止互等与轮询。

## 3. 权限与副作用

- 写工作区外、装全局依赖、删除、发布/合并：逐项要用户批，不代批。
- 禁止以任何方式激活前台窗口或抢走用户当前会话。
- 不可逆操作先备份，回滚步骤写进交付。

## 4. 记录与追溯

- 单一状态源：项目 `docs/plans/` 状态表；实施计划只维护收尾表（含负责人列）。
- 验收证据写进计划文档：路径 + 命令 + 日期；本地排障材料不入库、不外传。
- 决策进 ADR，规则进 rules；同主题不另开第二份文档。

## 5. 变更

- 本组文件只增删条目、保持简洁；项目只引用不复述。
- 修改需用户批准；追加时校验前缀未变，行数守上限。

## 6. 交付前检查入口

- 项目交付前检查入口以派工卡指定的项目脚本为准；完整原需求、阶段交接与证据边界见 `work.md` §8，运行前置与临时资源收尾见 `ops.md` §9。
