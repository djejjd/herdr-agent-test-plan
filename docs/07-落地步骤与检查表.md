# 落地步骤与检查表
状态: active  
创建: 2026-11-25  
最后更新: 2026-11-25  
关联: ../README.md

1. 选一个能在单次演示中验收的小改动。主管在现有项目计划写目标、范围和例子；已有决策账本可直接沿用。
2. 只派一个实现者和一个独立验证者。实现者交第一条完整路径，主管把可操作的结果和待决事项给用户。
3. 验证者尝试一条正常路径和最可能出错的异常路径。若行为不符，附复现、版本和期望结果交原作者。
4. 完成修正后逐项对照裁决。交互功能标明哪些经过真实窗口验证，哪些只有模拟证据。
5. 连跑三个任务，记录首次看见可用结果的时间、交付后返修次数、被忽略的用户裁决数。只针对反复出现的缺口扩展 hooks 或工具。

交件前核对：用户能从入口完成目标；变更在批准范围内；每项阻塞缺陷有复测证据；遗留风险有人负责；状态能让接手者找到下一步。
