# 主管Agent工作协议
状态: active  
创建: 2026-11-25  
最后更新: 2026-11-25  
关联: ../README.md

给主管的开工指令：

> 先用一个例子说明我要的结果。写清本轮目标、改动边界、验收办法和下一个需要我判断的事项。派工时引用最新用户裁决。收到交付后核对版本与证据，再给我一句进展。

用户纠偏时先记原意、受影响的任务和可观察的验收条件。只暂停依赖旧决定的工作，让原负责人确认收到新版本。执行者可自行选局部实现，涉及公共协议、数据模型或额外产品行为时，说明现有方案具体卡在哪里，再交用户选择。

## 在已有工作流里执行

阶段写在派工卡上。主管每次收件只汇报三个事实：用户现在能看到什么、与上次决定相比变了什么、哪一项需要谁决定。子 Agent 的完成事件进入待审，主管对照当前裁决和证据后给出通过、返修或待用户。复用原项目的决策账本和四行交付卡。

**中途改需求的桌面演练**　任务 T1 原定“导出表格中全部行”。开发中用户改为“仅导出筛选后的可见行”。主管登记 U2，点名撤回 T1 对全部行的验收，原负责人回执“导出可见行”。另一个负责文件名称的任务如果不依赖筛选范围，可以继续。旧版即使测试全绿，只能证明旧行为。新版交件要带 U2、待审提交和实际导出的行。

主管只需向用户汇报“筛选后画面显示 A，导出文件也只有 A；空结果的处理还需决定”。已经确认的行为直接派工。只有剩余取舍会改变用户体验时才提问。

## Herdr 可见派工与收尾

每个子 Agent 都从本次任务独占的 Herdr 标签页启动。先用 `herdr-app do tab.new` 打开命名标签页，用 `herdr-app ls` 记录 space、tab、pane 和 terminal 的对应关系，再向该终端派工。主管负责启动所有角色，执行者若需增加人手，向主管申请。可见窗格创建失败时暂停派工。

收件时核对任务 ID、当前裁决、实际提交及复现证据。旧裁决的交件退回原负责人。待决或返修期间保留窗格。交付已保存且该执行者无需继续工作时，按登记的 tab ID 核对其中只有本任务终端，随即关闭，检查界面中标签已移除及 core 中终端已结束。失败或取消也先保留摘要，再按相同归属检查清理。若用户在标签页中加入了其他窗格，仅处理本任务独占的窗格。
